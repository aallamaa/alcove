# Alcove & Adder v0.5.0: The Persistence & Events Release

Welcome to v0.5.0 of Alcove and Adder — the persistence and events release. This update equips both languages with `lib/orm.adr` for robust, out-of-the-box object persistence, alongside a high-performance layer-2 keyspace watch stack for building reactive systems. Whether you are scripting in Alcove or writing Python-flavored Adder, you now have the primitives to persist complex states and react instantly to data mutations.

### Layer-2 Keyspace Watches & Blocking Consumption
We've introduced an opt-in event stream for keyspace mutations that operates via a lock-free MPSC queue, ensuring fast emission from any reactor thread. Consumers poll from the main thread via `redis-next-event!` or wait efficiently using the new blocking `redis-wait-event!` consumer, which sleeps on an eventfd (protected by Dekker fences against lost wakeups). 

*Adder-flavored keyspace watch example:*
```python
# Start watching the keyspace
redis_watch(True)

# Block for up to 5000ms waiting for a mutation
event = redis_wait_event(5000)
if event:
    print(f"Mutation observed: {event}")
```

### Object Persistence (`lib/orm.adr`)
A complete persistence layer for `defclass` models. It brings a suite of ORM capabilities including `orm/save` (upsert with auto-ids), `orm/get`, `orm/all`, `orm/query` (predicate scans), and `orm/delete`. Instances are cleanly persisted by their class name (dump v5), and class validators remain fully live and active after reloads.

### Build Variant Introspection
The `--version` flag now prints the complete build variant, making it trivial to identify your binary's architecture, threading model, active features, and fixnum width directly from the command line (e.g., `alcove 0.5.0 (amd64 threads jit ffi readline metrics fixnum61)`).

### Fixes
* **Fixed:** The combined REPL + RESP mode (`-R`) now properly issues a warning if it detects an ignored `--threads` flag (since `-R` is single-reactor), rather than dropping it silently.
* **Fixed:** Rewrote the "Bug 2" anonymous-lambda persistence regression test. It previously failed to run at all due to function-sugar syntax constraints, but now correctly executes a real savedb/loaddb round-trip assertion with tightened stderr baselines.
